# Anotacao-Doc

#area/trabalho #trabalho/anotacoes #conceito

**Resumo:** Anotações de documentação técnica lida ou produzida.

## Como usar
- Criar uma nota por documento ou por tema lido, extraindo o que é útil para o trabalho de QA.
- Registrar o link e a versão da documentação para consultar depois.
- Escrever com suas palavras o que entendeu, em vez de copiar o texto original.
- Atualizar quando novos fluxos ou endpoints forem descobertos.

## Estrutura
- **Fonte:** link, título, versão e data de acesso da documentação.
- **Resumo:** ideia central em poucas linhas.
- **Fluxos:** passos importantes de negócio ou técnicos extraídos do doc.
- **Referências:** termos, comandos, endpoints e configurações citados.
- **Glossário:** siglas e definições que aparecem com frequência.

## Dicas
- Foque no que afeta os testes: critérios de aceite, regras de negócio e contratos de API.
- Cite a página/seção do doc no bug para o dev entender de onde veio a expectativa.
- Documentação muda: confira a data e avise o time quando perceber que está desatualizada.
- Converta anotações de doc em casos de teste quando o conteúdo for regra de negócio.
