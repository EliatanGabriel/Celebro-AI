# S3

#area/estudos #estudos/cloud-e-devops #conceito

**Resumo:** Amazon Simple Storage Service: armazenamento de objetos altamente durável e escalável da AWS, usado para buckets, static hosting, backup e data lakes.

## Conceitos-chave
- **Bucket:** contêiner de objetos com nome globalmente único, região e políticas.
- **Objeto:** arquivo com key (caminho), metadata e versão; sem hierarquia real (prefixos simulam pastas).
- **Durabilidade e disponibilidade:** 11 noves de durabilidade (99.999999999%) via replicação interna.
- **Classes de storage:** STANDARD, INTELLIGENT_TIERING, STANDARD_IA, GLACIER (arquivamento) com custo/retrieval diferentes.
- **Versionamento:** múltiplas versões do objeto, protegendo contra sobrescrita/exclusão.
- **Segurança:** políticas de bucket, IAM, criptografia (SSE-S3/SSE-KMS), bloqueio de acesso público.
- **Static hosting:** servir site estático via S3 + [[CloudFront]].
- **Lifecycle:** regras para transicionar/excluir objetos automaticamente por idade.

## Exemplos

Criar bucket e habilitar versionamento:

```bash
aws s3 mb s3://meu-bucket-app --region us-east-1
aws s3api put-bucket-versioning \
  --bucket meu-bucket-app \
  --versioning-configuration Status=Enabled
```

Upload e sync:

```bash
aws s3 cp index.html s3://meu-bucket-app/
aws s3 sync ./dist s3://meu-bucket-app/ --delete
```

Regra de lifecycle (JSON):

```json
{
  "Rules": [{
    "Id": "arquivar-logs",
    "Status": "Enabled",
    "Prefix": "logs/",
    "Transitions": [{ "Days": 30, "StorageClass": "STANDARD_IA" }]
  }]
}
```

## Boas práticas
- Bloquear acesso público por padrão (Block Public Access) e usar presigned URLs.
- Habilitar versionamento e bucket policy para proteção contra exclusão acidental.
- Definir lifecycle rules para arquivar e reduzir custo.
- Usar Server-Side Encryption e bucket-level encryption (SSE-KMS).
- Forçar HTTPS e restringir acesso por origem/IP quando necessário.

## Armadilhas comuns
- Bucket público sem política, expondo dados (uma das falhas mais comuns na AWS).
- Confundir consistência do S3: hoje fortemente consistente, mas entender replicação cross-region.
- Nomes de bucket com caracteres inválidos ou muito curtos/longos (3–63 chars, minúsculas).
- Colocar TUDO em STANDARD mesmo dados que poderiam ir para IA/Glacier.
- Usar S3 como banco de dados relacional (latência e falta de queries nativas).
